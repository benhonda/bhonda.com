This is the reference for **`@adpharm/silo-analytics`** — Adpharm's drop-in replacement
for `@segment/analytics-next`. It re-exports the full analytics-next surface unchanged and
adds automatic engagement tracking, so **everything in Segment's analytics.js docs and the
tracking Spec still applies** — you just import from a different package and get extra
features for free.

**The one rule that changes everything:** in Adpharm apps you import from
`@adpharm/silo-analytics`, **never** `@segment/analytics-next`. The base reference below is
distilled from Segment's upstream docs with imports already retargeted to the wrapper.

**What the wrapper adds on top of vanilla Segment** (none of this exists upstream):

- **Time on Page** — automatic `Page Time Spent` events with SPA/SSR guardrails, a
  bounded-exponential heartbeat, tab/visibility awareness, and idle detection.
- **Scroll depth** — per-beacon scroll fields with an `est_` lossiness convention.
- **Consent stamping** — optional `analytics-consent-tools` integration (OneTrust / TCF /
  custom banner) that stamps every event.
- **Server-side dedup** — `messageId` / `page_view_id` / `sequence` on every beacon.

Read the **Wrapper specifics** section first — when it conflicts with the upstream base
(install, imports, defaults, config surface), the wrapper wins.

**Audit / review / wire — three Adpharm rules:**

1. **Check the installed version first.** This doc is the **latest** surface (`v2.1.5`). Every
   wrapper value-add — consent gating (GPC / Law 25 / `defaultMode` / ubid), heartbeats
   (`heartbeatSchedule`), idle (`idleSeconds`), scroll-depth, server-side dedup
   (`page_view_id` / `sequence`), single-object `load()`, `env` namespacing — is **v2-only**.
   `v1.x` ships none of it: only primitive sendBeacon-on-`visibilitychange` Time-on-Page
   (two-arg `load(settings, options)`, `apiHost`+`writeKey` required). Read the real version
   (`package.json` / lockfile, or the `/lib/vX.Y.Z/` CDN pin) before reviewing call sites. **If
   `< 2.0.0`: surface the upgrade first** (`bun add @adpharm/silo-analytics@latest`) — don't
   flag absent features as findings, nor the v1 two-arg `load()` / explicit `timeOnPage` as
   redundant (required there).
2. **`env` on `load()` is optional — not a finding.** Adpharm separates environments downstream
   on the Silo/Segment side, not via client-side storage-key namespacing, so the upstream
   `anonymousId`-bleed warning doesn't apply.
3. **Consent mode is a property-level business call — don't recommend opt-in.** `opt-in` vs
   `opt-out` (`silo.consent.mode`, per-writeKey in Remote Settings) is decided per audience with
   the owner + counsel; the privacy-compliance reference is *not* legal advice. A missing
   `consent` block / `consent.defaultMode` / an opt-out default are **not** findings. Answer
   honestly **if directly asked** "is this compliant?", else leave the choice to the owner.
   Caveat for the reader: `consent.defaultMode` (code) is only the CDN-outage fallback — live
   `silo.consent.mode` is the real gate.
